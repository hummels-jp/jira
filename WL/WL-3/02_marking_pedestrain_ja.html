スライド 2: 物体マーキング (Object Marking)

OpenDRIVE において、横断歩道や停止線などの「物体マーキング」はどのように記述されるか？

道路上の非車線平面マーキングについて、OpenDRIVE では <object> 要素内の <markings> 要素を通じて定義されます：

  • マーキングの分類： 横断歩道 (Crosswalks)、停止線 (Stopping-lines)、駐車スペース (Parking spaces) などの平面マーキングを網羅しています。
  • 定義方法： 物体の Bounding Box（境界ボックス）に基づく方法と、Outline Points（輪郭点）を参照して詳細にモデリングする方法の2つのモードをサポートしています。
  • 座標参照： <cornerReference> 要素によって物体の輪郭点 id を参照し、点と点をつなぐ直線や複雑なマーキング形状を定義します。

スライド 3: マーキング要素の属性一覧 (Attributes of the marking element)

OpenDRIVE で「物体マーキング (Marking)」を記述する際の主要な必須属性は何か？

表に示すように、路面マーキング（破線、実線、横断歩道など）を正確に表現するために、OpenDRIVE では一連の標準化された属性が定義されています：

  • 視覚属性： side (境界位置)、width (線幅)、color (色)、weight (太さ等級) がマーキングの基本的な見た目を決定します。
  • 物理寸法： zOffset (マーキングの厚み)、lineLength (実線部分の長さ)、spaceLength (破線の間隔) により、マーキングの 3D 幾何学的特性が構築されます。
  • 位置とオフセット： startOffset および stopOffset は、境界ボックスに対するマーキングの横方向の開始点と終了点のオフセットを定義し、これは正確な配置とセグメント化されたレンダリングを実現するために極めて重要です。

スライド 4: 輪郭点参照モデリング (CornerReference Modeling)

cornerReference を使用して複雑な路面マーキング形状を構築するにはどうすればよいか？

XML の例に示すように、OpenDRIVE では事前に定義された outline 点を参照することで、高精度な幾何構造を実現しています：

  • 核となるメカニズム： cornerReference 要素は id 属性を通じて outlines で定義された cornerRoad 点を直接参照します。
  • 幾何学的な合成： XML の例では、点 0 と 1 を関連付けて最初のマーキングを構築し、点 2 と 3 を関連付けて2番目のマーキングを構築する方法を示しています。この方法により、不規則な横断歩道や複雑な駐車エリアであっても、相互に関連する輪郭点のシーケンスとして正確に抽象化できます。
  • パラメーターの分離： この設計により、「幾何学的な点の座標定義 (outlines)」と「論理マーキングのレンダリング (markings)」が完全に分離され、複雑な道路網における平面マーキングの構成と保守が大幅に簡素化されました。

スライド 5: 物体参照メカニズム (Object Reference)

OpenDRIVE において、複数の道路にまたがる物体 (Object Reference) を関連付けるにはどうすればよいか？

横断歩道のように複数の車線や道路にまたがる物体に対して、OpenDRIVE は <objectReference> 要素を使用して論理的な接続を確立します：

  • 主な目的： 1つの道路上で物体を定義し、他の交差する道路ではその一意の ID を参照することで、重複したモデリングを回避します。
  • 利用シーン： 物体（例：横断歩道）が複数の道路にまたがる場合、シミュレーションシステムはこの参照メカニズムを通じて、関連するすべての道路が物理的・論理的な障害物を正しく認識できるようにします。
  • 柔軟性： laneValidity 要素を組み合わせることで、開発者はその参照がどの車線区間で有効かを正確に指定でき、複雑な交差点モデリングの効率と保守性が大幅に向上します。
