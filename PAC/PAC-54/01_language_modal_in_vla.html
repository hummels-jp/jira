Slide 1: Encoder-decoder 架构

Yann Lecun 观点：LLM 的架构命名在某种程度上是混乱而反常的。

  • Decoder-only (Prefix Decoder): 双向输入/单向输出，参数共享。
  • Decoder-only (Causal Decoder): 单向输入/单向输出，参数共享。
  • Encoder-Decoder: 双向输入/单向输出，不共享参数。
  • Encoder-only: 双向输入/双向输出，参数共享。

Slide 2: 注意力掩码设计 (Attention Mask)

设计原理

  • 全1矩阵 (双向): 用于 Encoder 部分，全量信息交互。
  • 下三角矩阵 (单向/因果): 用于 Decoder 部分，只可见历史信息。

颜色标识含义

  • 蓝色: 前缀 (Prefix) Token 间的双向注意力。
  • 绿色: 输入 Token 与输出 Token 间的注意力。
  • 黄色: 输出 Token 间的因果自回归注意力。

架构特性对比

架构任务特性
Encoder-Decoder / Causal Decoder训练：掩码语言模型；判别型；任务：预测遮蔽/预测下一句
Prefix Decoder训练：自回归语言模型；生成型；任务：预测下一个 token

Slide 3: 从规则驱动到数据驱动

传统 vs. 端到端自动驾驶

  • 传统系统: 传感器 → 感知 → 预测 → 规划 → 控制 → 执行器
  • 端到端系统: 传感器 → 端到端自动驾驶模型 → 控制 → 执行器

传统自动驾驶的局限性

  • 模块化累积误差: 各模块间传递不确定性。
  • 目标不一致: 各模块优化目标可能存在冲突。
  • 计算冗余: 多模块间存在重复计算。
  • 局部最优 ≠ 全局最优: 模块间无法实现整体最优。
  • 维护困难: 基于规则的决策系统复杂庞大。

Slide 4: 端到端自动驾驶的特点与挑战

端到端自动驾驶的特点

  • 自动驾驶第一性原理: 简化架构，回归本质。
  • 避免级联误差: 直接输出控制信号，减少模块间错误传递。
  • 消除计算冗余: 模型合并，计算效率更高。
  • 从规则驱动到数据驱动: 依赖海量数据而非人工编码规则。

端到端自动驾驶存在的挑战

  • 黑盒问题与可解释性: 决策过程缺乏透明度。
  • 安全保障性问题: 极端工况下的鲁棒性待验证。
  • 因果倒置问题: 数据中的相关性不等于现实中的因果关系。

Slide 5: LLMs 该如何赋能 Autonomous Driving?

核心赋能方向

  1. 利用 Common Sense 辅助决策: 引入常识推理提升复杂场景下的决策逻辑。
  2. 海量数据采集标注问题: 利用 LLM 自动化生成数据标注或优化数据挖掘流程。
  3. 交互能力: 增强车机交互与多模态意图理解。
  4. 处理非结构化数据: 提升对多模态输入（文本、图像等）的感知与理解。
  5. 故障诊断和反馈: 提供智能化的系统诊断与事故回放分析。

关键技术闭环

  • Driving Capability Domain: 通过 Simulator (仿真环境) 和 Offline Dataset (离线数据集) 不断扩展边界。
  • 数据反馈循环:
    • -- More Data: 推动能力提升。
    • -> Common Sense: 提升模型理解。
    • -> Corner Case: 针对长尾场景专项优化。

Slide 6: 特斯拉案例 – Randomization

提升自动驾驶系统的鲁棒性

通过在模拟环境中引入随机变量，增强模型在多变现实世界中的泛化能力：

1. 环境随机化 (Environmental Randomization)

  • 通过动态调整光照、天气、视角及场景细节，提升系统对复杂视觉条件的适应能力。
  • 确保模型在多变视觉干扰下仍能保持高精度的感知。

2. 交通流随机化 (Traffic Flow Randomization)

  • 模拟车辆与行人的随机行为轨迹，提升系统在动态复杂交通环境下的安全性。
  • 有效地缩小仿真环境与真实世界之间的“现实鸿沟”（Reality Gap）。

Slide 7: LLM4AD 范式 (LLMs in AD Pipelines)

展示了将大型语言模型（LLM）集成到自动驾驶（AD）流程中的核心架构。

架构分层设计

  • Inputs (输入层): 整合了多模态感知数据（LiDAR、摄像头、GPS、车辆动态）以及文本提示（Prompt）。
  • Modal (模型层):
    • Visual Network: 处理图像感知。
    • LLMs: 如 GPT 系列、Llama 系列，提供推理能力。
    • Multi-Modal: 如 RT-2, LLaVA, PaLM-E，实现多模态理解。
  • Tasks (任务层):
    • Planning: 行为、路径、意图规划。
    • Perception: 检测、分割、追踪、运动估计、轨迹预测。
    • QA: 问答系统。
    • Generation: 世界模型、扩散模型生成。

Slide 8: DriveGPT4 – Planning + Finetuning + QA

DriveGPT4: 采用可解释的端到端自动驾驶模型，结合预训练与微调范式。

核心工作流程

  • Finetune Datasets:
    • 使用 YOLOv8 进行物体检测。
    • 将检测结果、控制信号与视频 Captions 输入 ChatGPT，构建包含 28K 视频-文本对（16K 问答对 + 12K 对话）。
  • Pretrain: 固定 CLIP Encoder 和 LLM，使用 CC3M 和 WebVid-10M 数据集训练 Video Encoder。
  • Finetune:
    • 使用生成的数据对 LLM 进行微调。
    • 引入 80K 条指令微调数据以保持模型原始能力。

测试与评估

  • 数据集: BDD-X-Dataset（描述车辆行为及其因果关系）。
  • 评估指标:
    • 语言质量：BLEU4, CIDEr, METEOR, ChatGPT Score。
    • 控制精度：RMSE（控制信号预测）。

Slide 9: Driving with LLMs – Planning + Finetuning

核心理念：Fusing Object-Level Vector Modality for Explainable Autonomous Driving。

模型架构特点

  • 对象级多模态 LLM 架构: 基于 Llama2 + LoRA，专注于利用向量化表示作为输入。
  • 工作流:
    • 场景向量通过 Vector Encoders 和 Vector-Former 处理，转化为 Vector Embedding 输入 LLM。
    • 结合 Prompt Embedding，LLM 输出驾驶行为（加速、刹车、转向）及其逻辑解释。

数据与评估

  • 数据集: 由 10K 驾驶场景衍生的 160K 个 QA 数据集，通过 RL(PPO) 收集数据，并由 GPT-3.5 生成。
  • 自定义 Metric:
    • 感知任务: 交通灯检测准确率、交通灯距离预测 MAE。
    • 控制任务: 加速度、刹车压力、转向角预测的 MAE。

Slide 10: LLM4AD – Planning + Prompt Engineering

核心理念：Receive, Reason, and React (R3 范式)。

关键技术特征

  • Raw Sensor 规划: 使用 Prompt Engineering 将原始传感器数据转化为规划任务，并引入“思维链”（Chain of Thought）进行推理。
  • 任务定义分类: 在仿真环境中，将复杂的驾驶任务定义为分类问题，提升处理效率。
  • 工具化驱动 (Tools & Memory):
    • Tools: 利用不同函数接口描述 Prompt，增强模型的执行能力。
    • Memory: 引入记忆机制，存储并参考历史决策数据，提升长效决策的稳定性。

引用信息

"Receive, Reason, and React: Drive as You Say with Large Language Models in Autonomous Vehicles"

Slide 11: LLM4AD – Prediction (GPT-Driver)

研究主题：GPT-Driver: Learning to Drive with GPT。

核心工作流程

  • Pipeline: 感知与预测 (Perception and Prediction) + 自车状态 (Ego-States) → GPT 作为运动规划器 (Motion Planner) → 动作轨迹输出 (Motion Planning Results)。
  • 关键优势:
    • Prompt Engineering: 在该任务中效果优于 UniAD。
    • 历史推演: 成功利用自车历史行驶信息推演出速度和加速度变化。

评估分析

  • L2 指标: 反映行驶轨迹的拟合程度，作者指出该指标反映驾驶性能的合理性有待商榷。
  • 性能表现: 在 L2 (m) 和 Collision (%) 指标上均表现优异。

论文信息

Slide 12: LLM4AD – Diffusion 技术

核心目标与挑战

  • 解决痛点: 数据采集和标注成本高昂。
  • 技术难点:
    • 跨帧一致性 (Temporal Consistency)

  • DriveDiffusion: 引入 Layout 指导，按 Layout 生成特定单视角多帧及多视角单帧图像。

Slide 13: LLM4AD – World Model (GAIA-1)

研究主题：GAIA-1: A Generative World Model for Autonomous Driving (Wayve)。

核心技术流程

  1. 多模态编码：将视频、文本、动作数据编码为一系列 Token。
  2. 自回归预测：利用自回归 Transformer (World Model)，以过去的图像、文本和动作 Token 为条件，预测下一个图像 Token。
  3. 解码重建：通过 Video Decoder 将预测的图像 Token 以高分辨率映射回像素空间。

模型组成与涌现智能

  • 基础模型：视频编码采用预训练的 DINO，文本编码采用 T5-large。
  • 涌现能力：
    • 理解现实：掌握交通规则、避让逻辑等。
    • 生成能力：具备泛化性，可生成多样的行驶场景视频。
    • 上下文理解：深层理解驾驶环境的上下文信息。

参考文献

"GAIA-1: A Generative World Model for Autonomous Driving" (arXiv/2309.17080) - Anthony Hu et al., Wayve。

Slide 14: LLM4AD – Tracking 与 Detection

核心理念：Language Prompt for Autonomous Driving。

关键技术突破

  • NuPrompt 数据集：
    • 首次提出了针对驾驶场景的大规模语言提示集（基于 nuScenes）。
    • 构建了 35,367 个 3D 对象-文本对，每个语言描述平均涵盖 5.3 个对象轨迹。
  • PromptTrack 模型：
    • 基于 Transformer 架构设计的专用跟踪模型。
    • 利用文本提示（如 "The vehicles that are turning right"）结合图像特征实现精准的物体检测与轨迹跟踪。

工作流程 (Pipeline)

  1. 感知：多视图图像输入经 Image Encoder 编码。
  2. 推理：通过 Prompt Reasoning 模块，将文本描述与图像特征进行关联。
  3. 输出：生成 3D 边界框（3D Boxes）与运动轨迹（Motion）。

参考文献

"Language Prompt for Autonomous Driving" (arXiv/2309.04379) - 北京理工大学、澳门大学、旷视科技等团队。

Slide 15: LLM4AD – Pretrain (ICLR 2024)

研究主题：Prompting Multi-Modal Tokens for End-to-End Driving Imitation Learning with LLMs。

核心技术亮点

  • 关键策略：
    • Shared Cross-Modal Prompt: 仅训练此部分参数，其余模型组件保持冻结 (Freeze)。
    • 多模态融合： 将 BEV 特征与语言 Embedding 进行融合。
  • 性能评估： 引入了 bev-to-text 和 text-to-bev 作为关键评估指标。
  • 研究发现：
    • 引入知识图谱 (Knowledge Graph) 能显著提升性能。
    • Caption 生成任务同样能带来明显的性能收益。

实验数据基础

  • 基于 Nuscenes 数据集。
  • 论文链接: ICLR 2024 OpenReview

Slide 16: LLM4AD – Radar Spectra-Language Model

研究主题：Radar Spectra-Language Model for Automotive Scene Parsing (ICLR 2024 Under Review)。

模型架构 (Architecture)

  • 模块化设计：
    • Radar Encoder & Image Encoder: 并行提取传感器特征。
    • Text Encoder: 利用冻结的 CLIP 架构作为文本嵌入基准。
  • 特征交互 (a) vs. 推理 (b):
    • (a) 计算原始模态损失。
    • (b) 通过计算 Cosine Similarity 进行多模态对齐，最终输出场景解析的预测概率 (Predicted probabilities)。

关键技术特征

  • 数据基础： 基于 Nuscenes 数据集。
  • 参数策略： 采用 "Shared Cross-Modal Prompt" 技术，仅训练 Prompt 参数，其余部分均冻结 (Freeze)。
  • 评价指标： 采用 bev-to-text 和 text-to-bev 双向评估指标。
  • 研究洞察： 引入知识图谱和 Caption 生成任务均能带来显著的性能提升。

Slide 17: LLM4AD 最新数据集概览

概述：下表梳理了当前 LLM 在自动驾驶（AD）领域主流数据集的核心特征。

数据集特性分析

  • 模态多样性：大多数数据集（如 DriveLM, NuPrompt, Nuscenes-QA）基于 nuScenes，集成了 Camera, LiDAR, GNSS 等多模态传感器数据。

  • 开放状态：包含开源（如 BDD-x, HAD, Nuscenes-QA）与未开源两种状态，部分采用 Apache 2.0 协议。
