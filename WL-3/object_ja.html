Slide 2: 物体マーキング (Object Marking)

OpenDRIVE において横断歩道や停止線などの「物体マーキング」はどのように記述されますか？

道路上の非車線平面マーキングについては、OpenDRIVE では <object> 要素内の <markings> 要素を使用して定義されます：

  • マーキングのカテゴリ： 横断歩道 (Crosswalks)、停止線 (Stopping-lines)、駐車スペース (Parking spaces) などの平面標識を網羅します。
  • 定義方法： 物体に基づく Bounding Box（境界ボックス）による定義、または Outline Points（輪廓点）を参照した詳細なモデリングの2つのモードをサポートしています。
  • 座標参照： <cornerReference> 要素を使用して物体の輪廓点の ID を参照することで、2点を結ぶ直線や複雑なマーキング形状を定義します。

Slide 3: マーキング要素の属性一覧 (Attributes of the marking element)

OpenDRIVE で「物体マーキング (Marking)」を記述する際に必要な主要属性は何ですか？

表に示す通り、路面マーキング（破線、実線、横断歩道など）を正確に表現するために、OpenDRIVE では一連の標準化された属性が定義されています：

  • 視覚属性： side (境界位置)、width (線の幅)、color (色)、weight (太さのランク) がマーキングの基本的な外観を決定します。
  • 物理サイズ： zOffset (マーキングの厚さ)、lineLength (実線の可視部分の長さ)、spaceLength (破線の隙間の長さ) がマーキングの3D幾何学的特性を構築します。
  • 位置とオフセット： startOffset と stopOffset は境界ボックスに対するマーキングの横方向の開始点と終了点オフセットを定義し、正確な配置やセグメントごとのレンダリングを実現するために不可欠です。

Slide 4: 輪廓点参照モデリング (CornerReference Modeling)

cornerReference を使用して複雑な路面マーキングの形状を構築するにはどうすればよいですか？

XML の例に示すように、OpenDRIVE では事前に定義された outline 点を参照することで正確な幾何学構成を実現しています：

  • コアメカニズム： cornerReference 要素は id 属性を通じて outlines で定義された cornerRoad 点を直接参照します。
  • 幾何学的合成： XML の例では、点 0 と 1 を関連付けて最初のマーキングを構築し、点 2 と 3 を関連付けて2番目のマーキングを構築する方法を示しています。この方法により、不規則な横断歩道や複雑な駐車エリアであっても、相互に関連付けられた輪廓点のシーケンスとして正確に抽象化できます。
  • パラメータの分離： この設計により、「幾何学的な点の座標定義 (outlines)」と「論理的なマーキングのレンダリング (markings)」が完全に分離され、複雑な道路網における平面標識の設定とメンテナンスが大幅に簡素化されます。

Slide 5: 物体参照メカニズム (Object Reference)

OpenDRIVE において、複数の道路にまたがる物体をどのように関連付けますか（Object Reference）？

複数の車線や道路にまたがる物体（横断歩道など）に対して、OpenDRIVE は <objectReference> 要素を使用して論理的な接続を確立します：

  • 主な目的： ある道路で物体を定義し、他の交差道路では一意の ID を参照することで、重複したモデリングを回避します。
  • 適用シナリオ： 物体（例：横断歩道）が複数の道路にまたがる場合、シミュレーションシステムはこの参照メカニズムを通じて、すべての関連道路で物理的／論理的な障害物を正しく認識させることができます。
  • 柔軟性： laneValidity 要素と組み合わせることで、開発者はその参照がどの車線区間で有効かを正確に指定でき、複雑な交差点のモデリング効率と保守性が大幅に向上します。
